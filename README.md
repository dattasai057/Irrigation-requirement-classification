# Irrigation Requirement Classification

A 10-day educational ML capstone: classify whether an agricultural observation
is likely to require irrigation, using soil moisture, temperature, humidity,
crop growth stage, and recent rainfall.

- **Domain:** Agriculture
- **Task:** Binary classification
- **Models:** Logistic Regression, KNN, Decision Tree (foundational methods, tuned with `GridSearchCV`)
- **Selected model:** Logistic Regression (see `reports/technical_paper.docx` §Model Development for justification)
- **Prototype:** Streamlit app (`app/streamlit_app.py`)

## Dataset

**Expected inputs (per project brief):** soil moisture, temperature, humidity,
crop growth stage, recent rainfall.

**Important note on data source:** this project was built in a sandboxed
environment with no live internet access at code-execution time, so the
dataset (`data/irrigation_dataset.csv`, 2,400+ rows before cleaning) is a
**domain-realistic synthetic dataset** generated by `data/generate_dataset.py`,
rather than a direct Kaggle download. It is modeled on the schema and
feature/target relationships documented in real, publicly available
smart-irrigation sensor datasets that combine a capacitive soil-moisture
sensor with a DHT11 temperature/humidity sensor and a crop-stage/crop-type
label (the same sensor combination used in numerous Kaggle "Smart Irrigation
System" student datasets and reproduced, e.g., in the open-source project at
https://github.com/NitrrMCACommunity/Agriculture-Automation-, and discussed in
peer-reviewed comparisons of ML models for irrigation prediction such as
Olatunde et al., *"Comparative analysis of machine learning models for smart
irrigation systems"* and Bhavani & Thambi, *"Managing Irrigation Needs Based
on Smart Decisions Using Machine Learning"*, ICTACT J. Soft Computing, 2022).
The generation logic (`data/generate_dataset.py`) encodes real agronomic
rules — crop coefficients (Kc) by growth stage, soil field-capacity by soil
type, evapotranspiration driven by temperature/humidity, rainfall offsetting
depletion — plus injected missing values, duplicate rows and sensor-fault
outliers, so the EDA/cleaning steps have genuine issues to find.

**To use a real Kaggle dataset instead:** search Kaggle for a "smart
irrigation" / "soil moisture irrigation" dataset with similar columns, then:

```bash
pip install kaggle
kaggle datasets download -d <owner>/<dataset-slug> -p data/ --unzip
```

Rename/remap its columns to match the schema below (or edit
`src/preprocessing.py`'s `NUMERIC_FEATURES` / `CATEGORICAL_FEATURES` /
`TARGET_COL` to match the real file), then rerun `python src/train.py` — no
other code changes are required.

**Schema:**

| Column | Type | Description |
|---|---|---|
| `soil_moisture_pct` | numeric | Soil moisture (%) |
| `temperature_c` | numeric | Ambient temperature (°C) |
| `humidity_pct` | numeric | Relative humidity (%) |
| `rainfall_mm_last_7days` | numeric | Rainfall in the last 7 days (mm) |
| `days_since_last_irrigation` | numeric | Days since the field was last irrigated |
| `crop_stage` | categorical | seedling / vegetative / flowering / maturity |
| `soil_type` | categorical | sandy / loamy / clayey |
| `crop_type` | categorical | wheat / maize / rice / sugarcane / cotton / groundnut |
| `irrigation_required` | target (0/1) | 1 = irrigation likely required |

## How to run (VS Code / terminal)

### 1. Set up the environment

```bash
# from the project root
python -m venv .venv

# activate the virtual environment
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

### 2. (Optional) Regenerate the dataset

Already included as `data/irrigation_dataset.csv`, but to regenerate:

```bash
cd data
python generate_dataset.py
cd ..
```

### 3. Train and evaluate the models

```bash
python src/train.py
```

This prints tuning results for all 3 models, saves the best pipeline to
`models/model.pkl`, saves all metrics to `models/metrics.json`, and saves
EDA + evaluation plots to `reports/figures/`.

### 4. Explore the notebook

Open `notebooks/EDA_and_Modeling.ipynb` in VS Code (with the Jupyter
extension) or via:

```bash
jupyter notebook notebooks/EDA_and_Modeling.ipynb
```

### 5. Run the Streamlit prototype

```bash
streamlit run app/streamlit_app.py
```

Then open the local URL Streamlit prints (usually `http://localhost:8501`).

## Evaluation summary

See `models/metrics.json` and `reports/technical_paper.docx` §Results for
full numbers. All three models scored well (F1 ≈ 0.90–0.92, ROC-AUC ≈
0.97–0.99) on the held-out test set; **Logistic Regression** was selected for
its top F1/ROC-AUC combined with full interpretability (see technical paper
for the full justification and discussion of why real sensor data would
likely be noisier than this synthetic set).

## Limitations & scope

This is an educational prototype, not a production irrigation controller. See
`reports/technical_paper.docx` §Limitations and §Future Scope for a full
discussion (synthetic data, no real-time sensor integration, no geographic/
climate generalization testing, etc.).
